# フレンド登録：ローカル実装とFirebase設定

## 今回の範囲
利用者名の完全一致検索、申請、受信者による承認・拒否、送信取消、フレンド解除。
チャット、読書履歴共有、プライベートモードは実装しない。
グループ選択画面とログイン後画面の「フレンド」から開く。
利用者名は既存の usernames/{登録時の利用者名} のUIDで識別する。
関係の文書IDは2人のUIDをソートして `__` で連結。同じ組合せは1文書。
フレンド申請の作成・承認にはトランザクションを使う。
自分への申請・既存申請・既存フレンドの再申請は受け付けない。
閉じても申請・フレンドはFirestoreに残り、別端末でもUIDで取得できる。

## 新しいデータ
`friendships/{UIDペア}`:
- memberIds: 2人のUID配列
- fromUid / toUid: 申請者／受信者のUID
- fromName / toName: 申請時の利用者名
- status: pending または accepted
- createdAt / updatedAt: ミリ秒時刻

拒否・取消・解除は、この関係文書だけを削除する。作品や読書履歴は削除しない。
一覧のクエリは memberIds array-contains ログインUID。

`friendsAccess/config`: enabled: true（boolean）
管理者が専用ルールを反映・検証したあとで設定する。
未設定・false・取得エラーでは機能を有効化しない。
この有効化フラグを作る処理はアプリに含めていない。

## ルール案
同じフォルダーの firestore-friends.rules は、提示された既存ルールを基にした置換案。
friendships は当事者だけが取得でき、受信者だけが pending → accepted に変更できる。
UID・名前・memberIdsの変更は禁止。関係の削除は当事者だけ。
friendsAccess はログイン済みユーザーが読めるが、クライアントの書込みは禁止。
usernames は既存の読取りを維持し、UIDの他人による書換えを防ぐ。
それ以外のコレクションは、提示された既存の読取り・書込み条件を維持する。

既存の `match /{document=**}` に全件許可を残して追加する方式は不可。
重なるmatchのいずれかが許可すると操作可能になるので、この案では専用コレクションを
包括的な許可から除外している。
現在の作品・読書履歴の公開範囲を変更・保護する機能は今回含まない。

   - 受信者の承認のみ許可。送信者の自己承認・参加UIDの変更は拒否。
