# フレンド登録ルール検証結果

検証日：2026-10-08

## 実行環境と結果

Firestoreエミュレーター、隔離プロジェクト `demo-reta-friends`、127.0.0.1:8787 を使用。
`docs/firestore-friends.rules` のコピーで実行。
`scripts/test-friends-rules.cjs` の35件の権限チェックと4件のテストデータ準備がすべて成功（終了コード0）。
本番のFirestoreデータの取得・変更、ルール公開は行っていない。
ダミーUID alice / bob / charlie のエミュレーター専用認証を使用した。
Javaとエミュレーターは /private/tmp/reta-friends-rules-test に配置。システム全体へのJavaインストールは行っていない。

## 確認した条件

- ログインユーザーによる有効化フラグの読取りを許可、未ログインの読取り・クライアントの変更／削除を拒否。
- 未作成の関係文書の重複確認を許可（404、権限エラーではない）。
- 申請者によるpending作成、当事者の読取り、受信者による承認を許可。
- 送信者の自己承認、第三者の取得／承認／削除、未ログインの取得を拒否。
- 参加UIDの変更、acceptedからpendingへの変更、accepted直接作成、自己申請を拒否。
- 名前とUIDの不一致、送信者偽装、余計なフィールドの追加を拒否。
- 当事者による申請拒否、取消、フレンド解除を許可。
- 自分のUIDをarray-containsで指定した一覧取得を許可、第三者の無条件一覧取得を拒否。
- 他人の利用者名文書の書換えを拒否、自分の文書更新と新規利用者名登録を許可。
- enabled:falseのとき、関係の取得／承認／削除を拒否。

## 未確認の範囲

Consoleで公開済みのルールが検証対象と同じ内容であることは、利用者の提示内容を前提とする。
本番の有効化フラグの状態、実アカウント2名の画面操作、既存読書・共有読書の実機動作は、このテストでは確認していない。
